UniversalDevKit (UDK) — расширяемый набор C++-библиотек, из которого приложение подключает нужные компоненты. Поддерживаются MSBuild и CMake. Минимальный стандарт языка — C++17.

Сейчас проверена сборка Windows x64 в Debug/Release. Поддержка Linux/Android и выпуск NuGet/AAR развиваются отдельно.

## Подключение к приложению

**Visual Studio / MSBuild:** запустите [Scripts/Connect.cmd](Scripts/Connect.cmd), выберите solution, проект, компоненты и способ подключения. Нажмите Apply, перезагрузите solution и соберите приложение. Connect настроит ссылки и необходимые зависимости.

**CMake:** добавьте UDK в проект и подключите нужный target:

```cmake
add_subdirectory(external/UniversalDevKit)
target_link_libraries(MyApplication PRIVATE UniversalDevKit::ComponentA.Static)
```

ComponentA — условное имя: замените его именем нужного компонента. Для динамической библиотеки выберите ComponentA.Dynamic и обеспечьте её доступность при запуске.

Установленный CMake-пакет можно подключить через find_package вместо add_subdirectory. Команды и примеры — в [руководстве CMake](Docs/CMake.md).

## Какой способ подключения выбрать

| Способ | Как используется код |
|---|---|
| Shared, MSBuild | Исходники компонента компилируются внутри проекта приложения |
| Static | Компонент собирается отдельно; нужный код включается в приложение при линковке |
| Dynamic | Компонент собирается отдельно в DLL/SO, которая нужна при запуске |

Необходимые зависимости учитываются автоматически. Например, если ComponentA использует ComponentB, сборка подключает требуемый вариант ComponentB.

## Как устроен репозиторий

Код каждого компонента хранится в одном экземпляре. Публичные заголовки находятся в Includes/UniversalDevKit/, реализации — в Sources/, описания сборки — в Projects/.

Общий JSON-реестр перечисляет файлы компонентов и их зависимости. MSBuild и CMake используют этот реестр и одни исходники:

- Connect настраивает подключение к проекту MSBuild.
- CMake создаёт библиотечные targets при конфигурации проекта.
- Установленный CMake-пакет предоставляет готовые targets без исходного checkout.

Подробности реализации находятся в Docs; результаты локальной сборки — в !artifacts.

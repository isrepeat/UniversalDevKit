## Модули Connect

Загрузчик SolutionInjector передаёт события прогресса через необязательный ProgressCallback: этап, обработанные байты, общий объём и завершение. Консольный модуль рисует собственную шкалу с серым текстом и жёлто-оливковым заполнением. Загрузка и распаковка используют потоковое чтение .NET; проценты считаются по фактическим байтам. При неизвестном размере загрузки показывается движущийся индикатор и полученный объём без процентов. В перенаправленном выводе остаются только начало и конец этапа. Проверки SHA-256 сохраняются.

`Connect.ps1` импортирует `Module.Udk.Connection` и `Module.Udk.Console` по пути относительно скрипта. Все вызовы между модулями квалифицируются как `Module.Udk.Connection\New-UdkConnectionPlan`. Запуск через Connect.cmd и параметры Connect.ps1 сохраняются.

`Module.Udk.Connection` содержит реестр компонентов, чтение текущей схемы, расчёт плана и применение изменений к vcxproj/sln. `New-UdkConnectionPlan` не записывает файлы. `Invoke-UdkConnectionPlan` получает план и необязательные обработчики сообщений и подготовки SolutionInjector; модуль не зависит от консольного UI.

`Module.Udk.Console` содержит палитру, ввод пути, меню, таблицу зависимостей и навигацию. Wizard возвращает запрос, не изменяя проекты. Общие значения передаются параметрами; внутренние файлы подключаются только внутри своего psm1. `ConnectConsole.ps1` использует экспортированную функцию оформления для итогового статуса.

Фиксированная Windows x64-дистрибуция описана в `SolutionInjector.json`: URL GitHub Release, commit репозитория, SHA-256 архива и EXE. Архив содержит готовый EXE из репозитория SolutionInjector и app-local Visual C++ Runtime DLL. Соответствие EXE исходникам не подтверждено пересборкой.

`Scripts/PowerShell/GetSolutionInjector.ps1` скачивает архив, проверяет SHA-256 и распаковывает его в игнорируемый `!tools/SolutionInjector/<версия>/`. Проверенный архив используется повторно без сети. Параметр `-LocalPath` позволяет указать тот же EXE локально; runtime DLL должны быть рядом с ним либо runtime должен быть установлен.

Пример запуска из корня UniversalDevKit:

```powershell
./Scripts/PowerShell/Connect.ps1 -ProjectPath C:/WORK/Windows/Projects/UniversalDevKit.ConsumerTest/UniversalDevKit.ConsumerTest.vcxproj -Components Helpers,Diagnostic -SolutionPath C:/WORK/Windows/Projects/UniversalDevKit.ConsumerTest/UniversalDevKit.ConsumerTest.sln
```

Для локального EXE добавьте `-SolutionInjectorPath C:/WORK/SolutionInjector/bin/SolutionInjector.exe`.

По умолчанию Connect работает с решением: при запуске CMD без аргументов спрашивает путь к `.sln`, выбирает consumer из проектов этого решения, затем действие и компоненты. Единственный consumer выбирается автоматически. Проекты самой UniversalDevKit исключены из выбора. Параметр ProjectPath позволяет явно выбрать consumer, который должен входить в указанное SolutionPath. CMD также передаёт аргументы PowerShell-скрипту.

SolutionPath вставляет всю папку MsBuild из UniversalDevKit.sln, сохраняя её иерархию: Shared, Static, Dynamic и общие настройки. Затем Connect заменяет импорт Sources.targets на прямые Shared References выбранных компонентов и их зависимостей. В `.vcxproj` появляются `Import` с `Label="Shared"`, а в `.sln` — записи `SharedMSBuildProjectFiles`, связывающие Shared-проекты с consumer. Исходники не копируются и компилируются как часть consumer.

Специальный режим без изменения solution включается только флагом ProjectOnly:

```powershell
./Scripts/PowerShell/Connect.ps1 -ProjectOnly -ProjectPath C:/WORK/Windows/Projects/UniversalDevKit.ConsumerTest/UniversalDevKit.ConsumerTest.vcxproj -Components Helpers,Diagnostic
```

Этот режим использует Sources.targets. ProjectOnly и SolutionPath нельзя комбинировать.

Повторный запуск с тем же SolutionPath добавляет выбранные компоненты к уже подключённым и восстанавливает удалённые очисткой компоненты через повторную вставку без дубликатов. В меню Connect стрелки вверх/вниз выбирают компонент, влево/вправо — Shared, Static или Dynamic. Space отмечает режим; повторное нажатие снимает отметку, выбор другого режима переносит её. На компонент допускается одна отметка. Уже подключённые компоненты показывают текущий режим; снятая отметка оставляет прежнее подключение без изменений. Enter на Apply применяет выбор, Esc отменяет операцию.

Для скриптов доступен параметр `-ComponentModes @{ Helpers = 'Static'; Diagnostic = 'Dynamic' }`. Если Components не указан, имена берутся из ComponentModes. Shared остаётся режимом по умолчанию. Static добавляет ProjectReference, Dynamic дополнительно задаёт import-макрос API и копирует DLL из стандартного каталога артефактов UDK в OutDir consumer. Публичный UniversalDevKit.props импортируется отдельно. Переключение удаляет предыдущие управляемые ссылки и очищает неиспользуемые проекты решения. Режимы сохраняются в свойствах UniversalDevKit<Имя>Linkage. ProjectOnly поддерживает только Shared. Static/Dynamic-компоненты с зависимостями пока блокируются до записи: их библиотечные проекты ещё не описывают зависимости. Конфликт режимов для общей Shared-зависимости также блокирует операцию.

Для выборочного отключения передайте `-Disconnect -Components Diagnostic` или несколько имён через запятую. Удаляются только выбранные явные компоненты; режимы и зависимости оставшихся сохраняются. Без Components в обычной консоли открывается список: Space отмечает компоненты, Enter на Apply применяет выбор. В неинтерактивном запуске Disconnect без Components отключает все компоненты проекта.

Backspace возвращает к предыдущему этапу: компоненты → действие → проект → решение → ввод пути. Автоматически выбранный единственный проект пропускается при возврате. Для запуска с явным Disconnect этап выбора действия также пропускается. Выбор компонентов при возврате сбрасывается; файлы изменяются только после Apply. Esc отменяет всю операцию.

Звёздочка после имени обозначает компонент, который не выбран явно, но нужен транзитивно. Список пересчитывается при изменении отметок; снятие отметки с прежнего подключения в Connect не отключает его. `/` в английской раскладке или `.` в русской включает и выключает просмотр зависимостей активной строки: их имена подсвечиваются зелёным, полный транзитивный список выводится под меню. Для компонента со звёздочкой также показываются явные корневые компоненты, которым он нужен. В Disconnect зависимости тоже видны, но отдельно удалить автоматически подключённый компонент нельзя — необходимо отключить требующие его корни.

Disconnect с SolutionPath после обновления связей consumer вызывает `SolutionInjector prune --apply --json` для папки UniversalDevKit. Неиспользуемые проекты и пустые папки удаляются из решения; зависимости оставшихся компонентов и других consumer сохраняются, исходники остаются на диске. Перед очисткой SolutionInjector создаёт резервную копию решения. Неоднозначные зависимости блокируют очистку: выбранные связи consumer уже удалены, дерево сохраняется, причины выводятся предупреждениями. ProjectOnly не запускает очистку решения. Прежние записи Shared References с двумя GUID приводятся к стандартному формату при обновлении связей.

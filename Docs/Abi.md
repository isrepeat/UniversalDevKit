## Политика 0.x

Проверенный Windows-набор этого этапа: x64, Visual Studio 2026 toolset v145, VCToolsVersion 14.51.36231, Debug/Release. Runtime-сценарий проверяет /MD(d) и /MT(d), в том числе два consumer с разными CRT в одном solution без общего UniversalDevKitRuntime. Проверка других toolsets и метаданные установленного бинарного пакета остаются открытыми.

При обновлении UDK требуется пересборка consumer. Замена DLL/SO без пересборки пока не гарантируется. Несовместимые изменения публичного API требуют повышения minor-версии. Patch-выпуск сохраняет публичный API; это не обещание совместимости произвольных toolchains и CRT.

Version.json — единственный источник версии выпуска и поколения ABI. CMake читает его непосредственно, генератор создаёт Includes/UniversalDevKit/Version.h для C++ и Projects/MsBuild/UniversalDevKit.Version.props для MSBuild. Будущие NuGet/AAR должны читать тот же файл; упаковка пока не реализована.

После изменения Version.json запускается GenerateComponentProjects; режим -Check обнаруживает устаревшие метаданные. CMake отслеживает изменение Version.json для повторной конфигурации. Version.h хранится в Git для использования заголовков без запуска генератора у consumer.

Поле version содержит major.minor.patch. abiVersion — отдельное поколение двоичного интерфейса: при несовместимом изменении экспортированных сигнатур или расположения публичных объектов его увеличивают. Поколение 0 не обещает стабильность ABI. VERSION SO соответствует версии выпуска, SOVERSION — abiVersion; эти свойства обозначают версии, но не доказывают совместимость. SameMinorVersion ограничивает выбор CMake-пакета.

## Публичные заголовки

Генератор создаёт общий Export.h и отдельный <компонент>/Export.h. Публичные компилируемые функции и классы помечаются UNIVERSALDEVKIT_<КОМПОНЕНТ>_API. Shared/Static оставляет макрос пустым; Dynamic выбирает dllexport/dllimport на Windows и default visibility на Linux/Android. CMake скрывает остальные символы Dynamic по умолчанию. Внутренние глобальные функции помечаются UNIVERSALDEVKIT_API_LOCAL; локальные помощники можно размещать в анонимном namespace.

Сложное состояние новых публичных классов следует скрывать за реализацией в Sources. PImpl уменьшает изменения расположения публичного объекта, но не отменяет требований к ABI, сигнатурам и toolchain. Для каждого API документируются владение памятью, время жизни, исключения и потоковая безопасность. Независимый C-интерфейс добавляется при появлении реального сценария плагинов или других языков.

## Контракты текущих функций

Diagnostic Log и TryLog синхронно читают std::string_view: буфер принадлежит вызывающему коду, должен оставаться действительным и неизменным до возвращения. Функции не сохраняют указатель, не освобождают память и не гарантируют немедленный flush. Временная std::string допустима на время вызова. Для будущего асинхронного режима потребуется собственная копия текста до возвращения.

Log подавляет ошибки и не выпускает исключения. TryLog возвращает false при исключении или состоянии ошибки std::clog; запись может быть частичной. true подтверждает только успех операций потока, а не доставку сообщения или сохранение на диске. Состояние ошибки потока не сбрасывается библиотекой; его восстановление остаётся ответственностью приложения. Это диагностический вывод, а не гарантированное хранилище сообщений.

Вызовы Log/TryLog защищены одним mutex на экземпляр реализации Diagnostic. Независимые Static/Shared-копии в EXE и DLL не разделяют этот mutex; прямые записи в std::clog его также не используют. Diagnostic сохраняет возможность независимых экземпляров, а не становится process-сервисом. Повторный вход из обработчика вывода запрещён. Замена rdbuf, настройка исключений потока или изменение входного буфера должны выполняться без конкурентных вызовов логирования. Перед выгрузкой DLL приложение прекращает вызовы и завершает использующие её потоки. Общая синхронизация плагинов и безопасная выгрузка ещё требуют отдельных сценариев.

Helpers EndsWithLineBreak не сохраняет и не освобождает буфер, читает его синхронно и не выпускает исключения; пустой текст возвращает false, проверяется только последний байт CR/LF. IsPowerOfTwo не изменяет общее состояние и возвращает false для нуля. Square использует операции типа T: переполнение не проверяется, копирование и умножение могут выбрасывать исключения согласно контракту T.

Новые API создания объектов должны явно указывать способ освобождения, например парный Destroy в той же библиотеке. C-интерфейс не добавлен: текущий API рассчитан на совместимый C++ toolchain/STL; наличие noexcept и отсутствие передачи владения не отменяют требования ABI.

### Проверки контрактов

Установленный CMake-пакет проверяется Static/Dynamic-consumer в Debug/Release: пустое сообщение, временная строка, CR/LF, нулевой байт, 400 сообщений из четырёх потоков, ошибка потока с включёнными и выключенными исключениями, восстановление после ошибки. Проверяется noexcept у Log/TryLog. Этот сценарий использует /MD и один экземпляр Diagnostic; отдельные /MT DLL могут иметь собственные потоки CRT. Выгрузка плагинов и общая блокировка разных модулей этим тестом не подтверждаются.

## Проверки

Export-сценарий собирает тестовую библиотеку и отдельный consumer в Static/Dynamic Debug/Release Windows x64, проверяет таблицу экспортов DLL: публичная функция присутствует, внутренняя отсутствует. Реальные Linux/Android toolchains и экспорт ELF ещё не проверены. Подмена новой DLL старому EXE пока не является поддерживаемым сценарием; при введении такой гарантии потребуется отдельный тест совместимости.

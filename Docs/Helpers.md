# Helpers

`Preprocessor.h` перенесён из UtilityHelpersLib и подключается как `<UniversalDevKit/Helpers/Preprocessor.h>`. Сохранены имена макросов PP_*, PREPROCESSOR_*, FE_*, __VA_EXPAND и IF_VA_OPT_SUPPORTED, включая пределы исходной реализации: подсчёт до 63 аргументов, разворот до 10, FOR_EACH до 9. Для макросов с __VA_OPT__ в MSVC нужен /Zc:preprocessor; старые обходы препроцессора сохранены. Заголовок самостоятельно подключает utility для PP_FORWARD_CTOR. В отличие от старой версии, он не определяет NDEBUG: режим assert задаёт проект. При DISABLE_PREPROCESSOR_MESSAGES обе разновидности сообщений разворачиваются в пустую строку. PREPROCESSOR_FILE_INCLUDED по умолчанию отключён, как в исходной версии.

Collection и Event входят в тот же header-only компонент: namespace `universaldevkit::helpers::collection` и `universaldevkit::helpers::event`. Collection переносит четыре заголовка `Algorithms.h`, `fixed_container.h`, `iter_to_last.h`, `iterable_queue.h` из одноимённой папки UtilityHelpersLib. Extract сохраняет выбранные элементы через stable_partition перед перемещением в результат; remove_if не сохраняет удаляемые значения. Входные итераторы должны поддерживать используемые алгоритмы; Set::IsHasIntersection предполагает одинаковую сортировку по извлечённым значениям через operator<.

Event переносит новый API `IEvent.h` и `Signal.h`; старые корневые Event/Signal/WeakEvent и Windows EventObject не переносятся. Токен подписки необходимо сохранять: после уничтожения последней копии токена подписка перестаёт участвовать в новых вызовах. ScopedConnection отключает подписку при уничтожении. Signal хранит слабые ссылки на записи подписок, соединения безопасно переживают Signal. Invoke вызывает снимок обработчиков вне mutex в порядке подписки: отключение не отменяет уже созданный снимок, исключение обработчика прерывает вызов. Получатели методов должны жить до окончания всех вызовов; уничтожение самого Signal необходимо согласовывать с обращениями к нему извне. Зависимость от старого TokenContext не требуется. Новые поведенческие тесты для Collection/Event не добавлялись по запросу; заголовки включены в существующий HeaderCheck.

Helpers — header-only компонент C++20 с разделами Meta, Math, Patterns, StdExt, Stream, Regex, Collection и Event. Исходники находятся в Includes/Helpers/UniversalDevKit/Helpers/. Meta, Math и Patterns используют namespace universaldevkit::helpers::meta, universaldevkit::helpers::math и universaldevkit::helpers::patterns. StdExt использует namespace universaldevkit::helpers::stdext::extensions и автоматически предоставляет alias stdEx; ограничения первоначального переноса описаны в [Std.md](Std.md). Публичные пути начинаются с UniversalDevKit/Helpers/.

CMake предоставляет только UniversalDevKit::Helpers.Headers. В MSBuild доступны Helpers.Shared и проверочное приложение Helpers.HeaderCheck; Static/Dynamic вариантов нет. NuGet UniversalDevKit.Helpers использует linkage Shared. Android AAR: org.universaldevkit:universaldevkit-helpers-shared-release:<version>, Prefab target udk_helpers_shared::Helpers. Собственной .lib/.dll/.a/.so у Helpers нет.

Старый compiled-компонент переименован именно в HeleprsTest. Его API находится в UniversalDevKit/HeleprsTest/, namespace — universaldevkit::heleprstest::math и universaldevkit::heleprstest::text. Сохранены GUID прежних проектов, Static/Dynamic/Shared и пакеты UniversalDevKit.HeleprsTest. DiagnosticTest пока использует его как private/static тестовую зависимость; новый Helpers от HeleprsTest и DiagnosticTest не зависит.

Независимые компоненты Meta и Math, их проекты и пакетные адаптеры удалены. Совместимых обёрток для старых include/namespace не добавлено. Подробности API разделов — Meta.md и Math.md. Имена каталогов consumer-тестов MetaPackage и MathPackage сохраняются как названия тестовых наборов, оба используют Helpers.Headers.

Header-only не гарантирует единственный экземпляр скрытого static-состояния во всём процессе. Для общих сервисов используется явное владение либо отдельный динамический компонент со stateScope=process; см. StateScope.md.

Patterns/Singleton.h переносит Singleton, SingletonUnique, SingletonShared и SingletonUnscoped из UtilityHelpersLib. GetInstance создаёт объект без аргументов; если конструктора по умолчанию нет, сначала нужен CreateInstance(args...). Повторный CreateInstance возвращает уже созданный объект. Копирование Singleton запрещено. Варианты с указателями защищают создание и получение mutex; это не синхронизирует методы самого объекта. SingletonUnscoped требует явного DeleteInstance и внешнего согласования удаления со всеми пользователями указателя. Как и в исходном API, циклическая инициализация и обращения после уничтожения singleton не поддерживаются.

Consumer-тест Tests/Fixtures/Consumers/PatternsPackage проверяет параллельное первое обращение, повторное создание, передачу аргументов и удаление/повторное создание Unscoped.

Stream и Regex — дополнительные разделы того же header-only компонента, namespace universaldevkit::helpers::stream и universaldevkit::helpers::regex. Stream/StreamHelpers.h проверяет состояние стандартных потоков; StreamLineReader.h последовательно читает строки с peek-буфером и ограниченной историей; StreamLineViewer.h загружает позиционируемый поток в собственный буфер и возвращает string_view на строки. Regex/Regex.h предоставляет поиск совпадений и групп над std::regex, включая владеющие строки и невладеющие view. fstreamEx использует эти реализации напрямую; временного LegacySupport.h больше нет.

StreamLineViewer восстанавливает внутренние views при перемещении и явно требует позиционируемый поток; ошибки позиционирования и неполное чтение вызывают исключение. Reader возвращает индекс в сохранённой истории после вытеснения; GetHistoryLine заменяет вводящее в заблуждение имя LookAhead, сохранённое как deprecated alias. Regex-view требуют живого неизменного исходного буфера, временные строки для view-результата отклоняются. Поиск внутри тегов остаётся специализированным текстовым поиском, не полноценным парсером разметки. Исключения StreamHelpers переносимы.

Tests/Fixtures/Consumers/StdPackage проверяет основные возможности Reader, Viewer, owning/view regex-результаты, форматирование пути и интеграцию fstreamEx с чтением CodePage. Отдельные тесты перемещения и расширенная матрица ошибок не добавляются. Контракты и ограничения описаны в [Std.md](Std.md).

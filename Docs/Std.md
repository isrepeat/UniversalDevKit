# StdExt: standard library extensions

Раздел сохраняет вложенную структуру Extensions/rangesEx и API universaldevkit::helpers::stdext::extensions. Каждый заголовок расширения подключает Config.h и автоматически предоставляет alias stdEx. STD_EXT_NS удалён. Алгоритмы ссылок, владения, чтения файлов и range-адаптеров исправлены без смены этой архитектуры.

Публичные include начинаются с UniversalDevKit/Helpers/StdExt/. fstreamEx использует общие Helpers/Stream/StreamHelpers.h и Helpers/Regex/Regex.h через относительные include.

## Ссылки и указатели

optional_ref принимает только совместимые lvalue-объекты: конструирование и присваивание из временных объектов запрещены, включая optional_ref<const T>. value_or также требует совместимый lvalue. Преобразования optional_ref и reference_wrapper сохраняются. Тип не продлевает время жизни объекта.

Указатели проверяются стандартными средствами: if (pointer), сравнение с nullptr и weak.lock(). Пользовательские Try, SafeObject, SafeConditionResult, SAFE_RESULT и связанный bad_pointer удалены. Методы As/Cast сохраняются.

unique_ptr<T, Deleter> допускает собственный deleter для обычного владения. Передающие владение As<U>/Cast<U> доступны только для default_delete<T>, не для массивов; целевой тип должен совпадать с T, иметь виртуальный деструктор или быть final. Небезопасный upcast и перенос неизвестного deleter отклоняются при компиляции. Неудачный As возвращает пустой указатель, Cast бросает std::bad_cast; исходное владение при этом сохраняется. Массивы поддерживают обычное владение, но не ownership-cast.

Методы Is/AsView и shared_ptr::As/Cast ограничены допустимым dynamic_cast с сохранением const; массивы и несовместимые типы отклоняются в сигнатуре. shared_ptr::As/Cast сохраняют общий control block и исходный deleter. Пустой As возвращает пустой указатель, пустой Cast бросает std::bad_cast.

## Чтение файлов

BOM проверяется в явном порядке: UTF-32, UTF-8, UTF-16. Публичная таблица KnownUTFByteOrderMarks сохранена. Пробное чтение не устанавливает eofbit/failbit на коротких и пустых файлах и восстанавливает позицию. Для байтовой обработки файл необходимо открывать с std::ios::binary.

ReadData вызывается в начале открытого потока. BOM исключается из данных; строка CodePage=... ищется после BOM. Если заголовок найден, первая строка исключается из payload, включая случай без завершающего LF. Если заголовка нет, payload полностью сохраняется. Это извлечение байтов и метаданных, а не перекодирование UTF-16/UTF-32.

## Range-адаптеры

- drop_last(n) использует пару forward-итераторов с опережением на n, без временного take_view и предварительного полного обхода. Поддерживаются владеющие, несчётные конечные и бесконечные forward-range. size пересчитывается по текущему источнику; источник можно менять между обходами, с обычными ограничениями инвалидирования итераторов во время обхода.
- concat поддерживает move-only input-итераторы. Временный или перемещённый closure передаёт владение вторым view; повторное использование lvalue-closure доступно только для копируемого view. Iterator остаётся input-итератором и зависит от времени жизни содержащего view.
- flatten_tree выполняет preorder-обход конечного ациклического дерева. Узлы должны копироваться, но не обязаны иметь конструктор по умолчанию. Пропускаются только nullable-узлы, сравнимые с nullptr; числовой ноль и false сохраняются. Callback принимает Node&, возвращает input_range того же типа узлов и может быть mutable или move-only. Callback хранится во view; view должен пережить итераторы. Ссылочные диапазоны из callback не копируются как контейнеры, но элементы копируются в очередь обхода. Обнаружение циклов не выполняется.
- to<Container>() сохраняет семантику копирования/ссылок даже для rvalue-контейнера. Для явного потребления элементов используется to<Container>(stdEx::views::move_elements). Путь перемещения использует ranges::iter_move, включая proxy-итераторы. Контейнер должен поддерживать вставку через insert(end(), element); vector, set и map покрыты тестами. Рекурсивное преобразование вложенных контейнеров не выполняется.

## Проверки и оставшиеся ограничения

StdPackage проверяет совместимость старых вызовов, StdContract — запрет временных ссылок и небезопасных ownership-cast, однократное удаление, сохранение владения при ошибке, все BOM, пустые/короткие файлы, CodePage после BOM и без LF, владеющие и несчётные диапазоны, move-only итераторы/callback и явное перемещение unique_ptr.

Debug/Release runtime-проверки выполняются на Windows/MSVC. Contract.cpp также проверяется компилятором Android NDK r27c для arm64 и x86_64; это проверка компиляции, не запуск на Android.

## Форматирование пути

Стандартный std::filesystem::path больше не специализируется. Используется собственная владеющая обёртка universaldevkit::helpers::stdext::Path(path): std::format("{}", universaldevkit::helpers::stdext::Path(path)). Узкий формат передаёт байты path.u8string(), широкий декодирует UTF-8 в wchar_t с учётом UTF-16/UTF-32 и отклоняет некорректную последовательность через std::format_error. Преобразование не зависит от текущей locale. Ширина, выравнивание и точность делегируются стандартному string_view formatter. Прямые вызовы std::format с filesystem::path в C++20 необходимо заменить на обёртку.

## Stream и Regex

StreamLineViewer читает весь позиционируемый поток с начала. Ошибки seek/tell, неполное чтение и недопустимый размер вызывают исключение; непозиционируемые потоки явно не поддерживаются. Перемещение восстанавливает внутренние string_view, включая SSO-буфер. Уже выданные views/spans инвалидируются при перемещении и уничтожении Viewer.

StreamLineReader читает последовательно и не требует seek. ReadLine(outIndex) возвращает индекс в сохранённой истории после вытеснения, а не абсолютный номер строки. Ёмкость 0 по-прежнему означает 1; ёмкость больше INT_MAX отклоняется. GetHistoryLine(0) возвращает последнюю прочитанную строку, GetHistoryLine(1) — предыдущую; LookAhead оставлен как deprecated alias. Ошибки чтения отделены от нормального EOF, включая последнюю строку без LF при включённых исключениях потока.

Regex по умолчанию возвращает заимствованные string_view: исходный текст должен оставаться живым и неизменным. Для таких результатов rvalue std::string/std::wstring отклоняются при компиляции. Временные строки разрешены с owning-результатом, например GetRegexMatch<char, std::string>(std::string("code=42"), regex). Явное создание string_view из временного буфера не продлевает его жизнь и остаётся ответственностью вызывающего кода. Поиск внутри тегов является специализированным regex-поиском, а не парсером разметки.

Существующий consumer проверяет основные возможности. Android-проверка включает компиляцию Main.cpp с narrow/wide форматированием, Reader, Viewer и Regex для arm64/x86_64; runtime на Android не подтверждён. Проверки не являются исчерпывающей матрицей ошибок потоков и времени жизни объектов.

# Пакеты UniversalDevKit

XAML: UniversalDevKit.XamlRuntime и UniversalDevKit.OpenGLESRenderer поставляются через Windows native NuGet и Android AAR/Prefab. Windows использует MD/MDd и общий Diagnostic DLL; renderer дополнительно доставляет ANGLE. Отдельный host-пакет UniversalDevKit.XamlCompiler выпускается командой Scripts/Packages/Windows/Pack.XamlCompiler.cmd. Подробнее: [XamlRuntime](../Docs/XamlRuntime.md).

Android Kotlin AAR: [AndroidCoreSdk](Android/AndroidCoreSdk/README.md) и [AndroidAppKit](Android/AndroidAppKit/README.md). Они сохраняют Maven-координаты com.isrepeat и собственные версии в gradle.properties. Адаптер gradle-publish в PackageTools использует общий toolchain UDK без NDK; releaseDependencies пакета AppKit предварительно выпускает CoreSdk. Это самостоятельные Kotlin-пакеты, не компоненты C++/Prefab.

Проверка Kotlin-поставки: `./Tests/Integration/Packages/AndroidKotlin.Tests.ps1`. Тест публикует оба пакета в новый feed под !artifacts, копирует независимый consumer и компилирует его через Maven-зависимость AppKit, включая транзитивный API CoreSdk. Запуск на устройстве этим тестом не проверяется.

Реальные компонентные поставки: [Windows native NuGet](Build/NuGet/README.md) и [Android Maven AAR/Prefab](Build/Android/README.md). Обе используют реестр рабочих компонентов и Version.json. Для Android подтверждены NDK-сборка и сборка APK; запуск на устройстве остаётся отдельной проверкой.

Тестовые заглушки разных способов доставки находятся в Tests/Fixtures/Packages. Команда Tests/Infrastructure/BuildTestPackages.ps1 выпускает их в явно указанный временный каталог; Android Maven собирается отдельным Gradle-сценарием теста. Это не новые продуктовые записи Package.json. Матрица покрытия существующих NugetProjects и Android AAR описана в [проверках доставки](../Tests/Integration/Packages/README.md).

Для выпуска конкретного NuGet-пакета запускайте Scripts/Packages/CrossPlatform/Pack.Helpers.cmd, Pack.Diagnostic.cmd, Pack.XamlRuntime.cmd или Pack.OpenGLESRenderer.cmd. Helpers выпускает header-only пакет; Diagnostic, XamlRuntime и renderer используют Dynamic CRT. Previewer и PluginSDK выпускаются в отдельном репозитории AndroidAppPreviewer.

Пакеты группируются по назначению: CrossPlatform, Windows и Android. Каждый пакет содержит Package.json и Delivery/<способ>/ с описаниями доставки. Категория CrossPlatform обозначает назначение продукта; фактически проверенные платформы перечисляются в Delivery.json.

Рабочие кроссплатформенные поставки находятся в CrossPlatform и ссылаются на компоненты UDK без копирования исходников. Реализация всех компонентов находится в Sources/<имя>, публичные C++ заголовки — в Includes/<имя>, проекты сборки — в Projects/<система>/<имя>; внутри Packages остаются описание выпуска, delivery-манифесты и файлы интеграции. Пустые каталоги не создаются.

Все продуктовые Package.json используют schemaVersion: 2 и локальные projects/contents. Основная точка запуска UDK — Packages/Build/Build.ps1, вызывающая общий Sources/Windows/UdkCli/Tools/PackageTools/Build.ps1. Для выпуска всех пакетов используйте ./Packages/Build/Build.ps1 -All; для проверки описаний без сборки добавьте -Plan. Список пакетов определяется автоматически по Package.json. Native-подготовку выполняют udk-native и udk-prefab, Kotlin — gradle-publish, инструменты и шаблоны — files; упаковку выполняют общие delivery-адаптеры. Версия компонентных пакетов задаётся в `Package.json` ссылкой `${UDK_VERSION.version}`. Готовые пакеты и промежуточные файлы — в !artifacts.

Собственные nuspec, targets и при необходимости props находятся непосредственно в Delivery/NuGet каждого пакета. Они перечислены в Delivery.json: nuspec и integration. Props/targets копируются без подстановок и могут содержать индивидуальную логику. Общий упаковщик генерирует данные выпуска и рассчитанные настройки графа в Generated/Settings.props и Settings.targets; пакет подключает их явными imports.
Android host-инструменты: [AndroidBuildTools](Android/AndroidBuildTools/README.md) и [AndroidTemplates](Android/AndroidTemplates/README.md). Общий files-адаптер PackageTools выпускает самостоятельные NuGet с собственными Version.json, без C++-компонента и без изменения версии при упаковке. CMD-точки входа находятся в Scripts/Packages/Android. Новый шаблон использует UDK AAR/Prefab, Diagnostic и отдельный XamlCompiler; Windows preview использует пакеты PluginSDK и WPF-превьювера из отдельного репозитория AndroidAppPreviewer; ID пакетов сохранены. UDK выпускает [PackageTools](Windows/PackageTools/README.md) для внешних репозиториев; native-зависимости SDK восстанавливаются из существующих отдельных пакетов XamlRuntime, OpenGLESRenderer и Diagnostic.

Размещение реализации, инструментов и шаблонов: [структура исходников](../Docs/SourceLayout.md).

# Очистка runtime DLL

Проверка: `powershell.exe -NoProfile -File Tests/Infrastructure/TestRuntimeCleanup.ps1` из корня UDK.

MSBuild Runtime.targets получает фактические DLL, затем SyncRuntimeLibraries.ps1 синхронизирует их с OutDir. Каталог .UniversalDevKitRuntime внутри OutDir содержит отдельный JSON-список каждого consumer/конфигурации/платформы; имена владельцев хешируются. Список включает имена, SHA-256 и признак владения файлами. Изменённые вручную DLL сохраняются. Существующая идентичная DLL без владельца также сохраняется после отключения.

Общий OutDir поддерживается для одинаковых DLL. Разные версии одной DLL у двух владельцев отклоняются до копирования: используйте отдельные OutDir. Блокировка сериализует доставку в один каталог. Устаревшая DLL удаляется только после отказа последнего владельца и при совпадении сохранённого хеша. Удалять вручную каталог учёта не следует: после его потери файлы считаются внешними.

Connect после полного Disconnect оставляет импорт с Label UniversalDevKitRuntimeCleanup. При следующей успешной сборке проекта пустой runtime-набор очищает файлы этого consumer. Импорт сохраняется и не подключает компоненты; следующий Connect заменяет его обычной интеграцией. Если checkout UDK уже удалён, условный импорт пропускается и автоматическая очистка невозможна. Другие конфигурации очищаются при их последующих сборках; изменение OutDir не удаляет файлы из прежнего каталога.

Механизм применяется к подключению через Connect/ProjectReference. Доставка native NuGet пока использует собственные targets; включение этого механизма в пакеты требует упаковки скрипта и общей интеграции и здесь не выполняется.
